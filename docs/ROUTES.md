# 路由规范

这份文件是这个站点长期维护的约定。新增页面前先读这里，按规则走，就不会出现 `/blog` 和 `/notes` 并存、`/tools/xxx` 和 `/tool/xxx` 混用这类问题。

---

## 一、三条铁律

**第一条：一级路径只放"内容类型"，永远是英文复数名词。**

`/tools`、`/notes`、`/lab` —— 看到路径就知道里面装的是一堆同类东西。
一级路径里不放单篇内容、不放年份、不放功能按钮。

**第二条：已发布的 URL 永不修改。** 需要改的时候登记 301 重定向（写在 `astro.config.mjs` 的 `redirects` 里），保证旧链接和人分享出去的地址不会 404。

**第三条：新增内容优先复用已有板块，不轻易新增一级路径。**
一级路径每多一个，导航就乱一分。真要新增，走下面第三部分的五个标准动作。

---

## 二、路由表

| 路径 | 页面类型 | 内容来源 | 说明 |
|---|---|---|---|
| `/` | 首页 | 聚合 | 最新条目 + 一句自我介绍 |
| `/tools` | 列表 | `src/content/tools/` | 藏品（网站、应用推荐） |
| `/tools/[slug]` | 详情 | 同上 | 单条推荐，五段式写法 |
| `/notes` | 列表 | `src/content/notes/` | 笔记（长文） |
| `/notes/[slug]` | 详情 | 同上 | 单篇文章 |
| `/lab` | 列表 | `src/content/lab/` | 车间（自制工具） |
| `/lab/[slug]` | 作品页 | 同上 | 可整页运行的作品 |
| `/about` | 单页 | 手写 | 关于我 |
| `/search` | 功能页 | Pagefind 索引 | 全站搜索 |
| `/rss.xml` | 输出 | 自动生成 | 订阅源 |
| `/404` | 兜底 | 手写 | 找不到页面 |

**层级上限是两层。** 不要出现 `/tools/分类/条目` 这种三层结构，分类用筛选参数解决，不占用路径。

---

## 三、新增一个板块的标准动作

按顺序做完这五步，新板块就和老板块平权，不会互相干扰：

1. 建目录 `src/content/<板块名>/`，以后所有条目都放这里。
2. 在 `src/content/config.ts` 里注册这个 collection，并用 zod 定义它的 frontmatter 字段。
3. 复制一份列表页和详情页：`src/pages/<板块名>/index.astro` 与 `[slug].astro`。
4. 在 `src/consts.ts` 的 `NAV` 数组里加一项，导航会自动多出一个入口。
5. 本地验证两个地址都能打开：`/<板块名>` 和 `/<板块名>/任意条目`。

**判断该不该新增板块，用这一条：** 里面会不会装**一堆同质条目**？
会 → 新板块。只有一篇 → 归到已有板块里当一条内容，别开新路径。

---

## 四、slug 命名规则

- 全部小写英文，单词之间用连字符：`raycast-vs-alfred`
- 不用中文、不用拼音、不用下划线、不用大写字母
- 长度控制在 3–5 个单词，能被一眼看懂
- 由 `npm run new` 命令自动从标题生成，生成后人工确认一次再落盘

理由很实际：中文 slug 在分享到聊天软件时会变成一长串 `%E5%B7%A5%E5%85%B7`，没人愿意点。

---

## 五、禁止事项清单

| 禁止 | 原因 |
|---|---|
| `/blog` 和 `/notes` 同时存在 | 同一类内容两个入口，读者和你自己都会迷路 |
| `/tool/xxx`（单数）和 `/tools`（复数）混用 | 命名不一致，链接容易写错 |
| `/2026/10/17/post-name` 这种日期路径 | 改标题或补发旧文时路径就失控了 |
| 用 `?id=123` 作为主内容地址 | 搜索引擎不友好，也不好分享 |
| `/page2`、`/more`、`/list2` 这类占位路径 | 一旦上线就再也删不掉 |
| 中文路径 | 编码后可读性极差 |

---

## 六、加页面之前先问自己

1. 它是**一堆同类东西**，还是**一个独立页面**？
2. 能不能塞进现有板块？能就别开新路径。
3. 它需要一个能被分享的独立地址吗？不需要的话用页面内锚点或筛选参数。
4. 五年后别人看到这个路径，能猜到里面是什么吗？

四个问题都过了，再动手建路由。
